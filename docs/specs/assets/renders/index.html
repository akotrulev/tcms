The whole product, in one design language

The case-authoring redesign settled a direction on one screen. These nine renders carry it across the other forty-two, grouped by what the screen is for rather than by where it lives in the rail — because the same shape serves ten index tables, and drawing it ten times would have hidden that.

The written rules are in the design-language spec. The kit these pages share is tcms.css and shell.js. Open any file in a browser; nothing here needs a server.

Grouped by job, not by rail position

Ten screens are the same table with different columns. A file per page would have drawn that skeleton ten times and let the ten drift; a file per family draws it once and shows the nine variations against it.

Nothing here has been driven in a browser

Same caveat the case render carries. These are HTML written to communicate a direction — not evidence that any of it survives real content lengths, 1280px, or a fifty-step case.

Two findings are real defects, not proposals

The skipped/untested colour pair fails at 10.7 ΔE for full colour vision, and the product's accents cannot form a 3-series palette (2.5 ΔE under deuteranopia). Both were computed, and both are fixed in the kit.

The kit is a render kit, not the product's CSS

tcms.css exists to draw these. The app's tokens live in frontend/src/index.css and theme.ts; the two agree on palette and family so the port is a mapping, not a translation.
